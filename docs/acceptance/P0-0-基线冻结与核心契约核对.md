## 0.1 历史技术方案冲突裁决

产品总方案 V2 的技术章节曾提出“沿用旧服务端 `/api/activity/*`”以及优先沿用 Preact HUD 等旧项目技术假设。这些内容与用户后来明确的新仓库独立建设要求、以及 TECH-ARCH-V0.1 存在冲突。

本项目按以下优先级处理：

1. 用户明确的新项目边界与后续确认优先。
2. TECH-ARCH-V0.1 是 `infamous-specter` 的当前技术候选基线：React + TypeScript + Vite、Phaser 4.2.1、纯 TypeScript Game Core、独立 Learning Core、Dexie/IndexedDB、新 Fastify `/api/v1/*`。
3. 产品总方案 V2、PLAN-V3、第三层词库映射继续作为产品目标、玩法、学习证据和内容设计参考；其中旧服务端、旧 API 路径、旧 Preact 技术栈不继承。
4. 旧项目的 API fixture、数据库记录、g3 行为或测试通过记录，不能充当新项目的 API/数据/验收证据。

因此，旧版 P0-0 文档中针对 `match-quest/connect`、旧 g3 和 `/api/activity/start|next|judge|event|finish` 的字段映射，只能作为历史审查材料，不属于本项目 P0-0 的执行对象。

## 0. 执行结论

P0-0 的目标不是“把旧 API 接起来”，而是把新项目从产品方案落到可验证的工程合同，确保后续每一款游戏都使用同一套内容、事件和学习证据规则，同时保留各自独立的核心循环。

当前确认：

1. 产品方向为学生自主使用的英语游戏库，V1 正式名册候选为 G01–G10；不是十个换皮答题页。
2. 五维能力分别记录：识义、听辨、拼写、词形、语境；证据基本粒度为 `word_id + sense_id + dimension + task_type`。
3. 游戏表现、语言任务结果、路线/结构奖励必须分开；路线奖励不得进入 E0–E3。
4. 新项目采用 React + TypeScript + Vite、Phaser 4.2.1、纯 TypeScript Game Core、独立 Learning Core、IndexedDB + Dexie、PWA；服务端是新建 Fastify 模块化单体 + PostgreSQL。
5. T1 技术样板已有自动化验证记录；这只证明应用壳、Phaser、输入、IndexedDB 和 PWA app-shell 在 CI/Playwright 场景下可运行，不代表真机、低端设备、读屏、正式学习证据或服务端能力通过。
6. 现阶段没有新项目生产 API、正式词库、Learning Core、E0–E3 判定器或跨设备同步实现；这些均不得写成已完成。

**P0-0 当前判定：未关闭。** 本轮先形成候选注册表与契约，后续逐项取得可复核证据并完成产品所有者裁决。未关闭前不进入正式游戏开发扩张。

## 3. 正式游戏注册表（候选 V0.1）

注册表结构化文件：`docs/contracts/game-registry.candidate.v0.1.json`。本节是其解释与验收口径。当前状态为候选，不代表十款均已开发或通过儿童试玩。

| ID / 游戏 | 独立核心循环 | 主要语言动作 / 维度 | 关键状态事件候选 | 主要风险与验收门 |
|---|---|---|---|---|
| G01 词岛大冒险 | 探索地图、选择分岔；语言判断改变路线/机关状态 | 识义、语境 | `route_choice`、`gate_opened`、`route_branch_changed` | 若只是大厅/世界地图包装，不能算独立游戏；必须证明英语判断真实改变可达路线 |
| G02 拼写矿车 | 输入/组装字母与词形部件，正确拼写改变轨道或矿车部件 | 拼写、词形 | `spelling_submitted`、`track_piece_built`、`route_changed` | accepted variants 单点维护；正确答案先判后演；IME composition 期间不得提前判错 |
| G03 词语连连看 | 棋盘配对、路径连接、障碍/传送门、阶段棋盘和死局重排 | 识义、听辨 | `pair_selected`、`pair_matched`、`path_rejected`、`board_rearranged` | 路径合法性与语言正确性分离；seed/replay 可复现；不得复用旧 g3 判题实现 |
| G04 词块消消乐 | 玩家主动选择并通过语义判断后消除/解锁，级联只清理已解锁区域 | 识义、语境 | `semantic_clear_accepted`、`cascade_clear`、`support_used` | C2 高风险；不进入 P3 首批先导，专项盲测/反事实不过则延后或回滚无支援原型 |
| G05 音速滑板 | 听音辨词并选择路线/车道，路线结果受语言判断影响 | 听辨、识义 | `audio_played`、`audio_replayed`、`lane_selected`、`route_changed` | 速度、反应时间不计学习证据；慢速、暂停、静态模式等价 |
| G06 变形工厂 | 组合词根/词缀/词形部件，规则校验后产出目标词 | 词形、拼写 | `morpheme_selected`、`form_assembled`、`form_verified` | 不能退化为普通字母拼写；适用词形规则审核，N/A 合法 |
| G07 句桥救援 | 排列词块、修复句子或搭建句桥；语境成立后改变桥梁状态 | 语境、词形 | `token_placed`、`sentence_submitted`、`bridge_segment_formed` | 允许经审核的多个合法句式；例句和搭配必须教研审核 |
| G08 易混词侦探城 | 对比近形/近音/易混词，选择目标词并指出结构化理由 | 识义、听辨、语境 | `contrast_pair_loaded`、`candidate_compared`、`reason_selected` | 解决“两个易混词该选哪个”；必须与 G09 的上下文推断循环不同 |
| G09 线索地牢 | 按自由顺序查看线索、缩小候选集合并提交推断 | 语境、识义 | `clue_opened`、`candidate_removed`、`hypothesis_submitted`、`abandon_partial` | 候选集合非空、非同质；线索必须有区分度；换词/放弃部分推理须可审计 |
| G10 岛心巨像 | 多阶段综合挑战；每阶段执行不同语言动作，语言结果改变 Boss 阶段状态 | 五维综合迁移 | `phase_started`、`phase_completed`、`boss_state_changed`、`review_task_created` | Boss 只是阶段目标，不是独立玩法本身；每阶段必须有不同语言动作；“单词怪兽战”暂作为 G10 机制候选，不新增 G11 |

### 3.1 注册表硬规则

1. 十款必须是十个不同的语言动作/核心循环，不是同一套答题模板换皮。
2. 每款至少提供：核心循环、玩家输入、语言动作、状态变化、可重放事件、学习证据上限、失败恢复、无障碍替代、传播画面和独立验收。
3. 游戏表现事件、语言任务事件、路线/结构奖励分开命名和存储。
4. 每种机关/路线类型必须明确其英语输入/判断、状态差异和可重放事件；没有语言因果链的装饰性机关不能宣称有学习价值。
5. G08 与 G09 若实际操作同质，必须重做或合并，不能仅靠名称区分。
6. G01 若不能证明独立循环，降级为全局地图/大厅；是否仍计入十款须由产品所有者裁决。
7. G04 不进入 P3 先导；G10 吸收“单词怪兽战”的正式映射仍待确认。

## 4. 内容模型与可导入词库合同

### 4.1 内容实体

| 实体 | 主键/关联 | 必需信息 | 约束 |
|---|---|---|---|
| Word | `word_id` | lemma、词性、年级标签、来源引用 | 一个词形可关联多个 Sense |
| Sense | `sense_id` + `word_id` | 中文释义、英文定义（可选）、标签 | 每个任务必须唯一绑定一个 sense |
| Pronunciation | `pronunciation_id` | IPA、口音、音频引用、来源、审核状态 | 音频必须绑定词义项；无审核音频不得宣称完成听辨 |
| Example | `example_id` | 英文例句、译文、目标 sense、年级、审核状态 | 语法、搭配、自然度、适龄性人工审核 |
| Asset | `asset_id` + version | 类型、hash、MIME、尺寸/时长、许可来源、作者、用途 | 未完成授权审查的素材不得进入正式包 |
| ContentPack | `pack_id + version` | 教材、年级、册次、单元、schemaVersion、contentHash | 发布后不可原地覆盖；会话固定启动时版本 |
| TaskTemplate | `task_template_id` | dimension、taskType、supportLevel、evidenceCap、answerSpecRef | 任务由内容/学习层定义，不散落在游戏 UI 中 |
| ContrastPair | `contrast_pair_id` | 词项/义项关系、对比维度、审核记录 | 不能把独立词误记为拼写变体 |

### 4.2 正式词条最小字段

```ts
interface WordRecord {
  wordId: string;
  lemma: string;
  partOfSpeech: string[];
  senses: SenseRecord[];
  gradeTags: string[];
  curriculumRefs: CurriculumRef[];
  sourceRefs: SourceRef[];
}

interface SenseRecord {
  senseId: string;
  glossZh: string;
  definitionEn?: string;
  pronunciationRefs: string[];
  exampleRefs: string[];
  imageAssetRefs: string[];
  acceptedSpellings?: string[];
  morphologyRules?: MorphologyRule[];
  tags: string[];
  reviewStatus: 'draft' | 'reviewed' | 'approved' | 'retired';
}
```

### 4.3 导入与审核规则

- 首版优先保证 JSON 与 CSV；XLSX 可作为后续便捷入口。
- 导入必须做字段、编码、空值、重复 ID、枚举、引用完整性和资源 hash 检查。
- 同形多义拆分 Sense；不同词不能通过 accepted variants 混在一起。
- acceptedSpellings / acceptedVariants 必须单点维护并版本化；G02/G10 对同一词项使用同一规范。
- 100 词纵切片指 100 个可追溯词条/词项，不是 100 道题；每个词项可以生成多个任务，但不得把同词换背景算成新词。
- 当前教材出版社、教材版本、册次、单元和官方 100 词清单未确认；现有演示词只能用于内部结构验证，不得宣称官方教材覆盖。
- 正式词包发布前，英语、音频、例句、词形、干扰项、游戏适配和证据映射均须有审核记录。

## 5. 五维学习证据合同

### 5.1 五维定义

| Dimension | 中文 | 可验证能力 | 不得混入 |
|---|---|---|---|
| `meaning` | 识义 | 看到英文能独立提取对应词义 | 有选项的四选一不能直接等同独立回忆 |
| `listening` | 听辨 | 听到发音能辨认目标词 | 音量、设备延迟、播放速度不能成为能力指标 |
| `spelling` | 拼写 | 无完整拼写提示下产出正确拼写 | 不能把未审核的近似拼写自动视为合法变体 |
| `morphology` | 词形 | 理解复数、时态、派生等适用规则 | 不适用词项允许 N/A，不强制凑题 |
| `context` | 语境 | 在短语/句子中理解并使用目标义项 | 未审核例句、存在多解的任务不能计证据 |

### 5.2 E0–E3 候选口径

| 等级 | 语义 | 示例 | 不可推断 |
|---|---|---|---|
| E0 | 接触/有提示参与 | 看过词、听过音、跟随示范 | 不代表识义、听辨或回忆 |
| E1 | 有支持的识别 | 选项、线索、部分字母、明确提示 | 不等于独立提取 |
| E2 | 同次练习中的无提示提取 | 不显示答案的识义/听辨/拼写 | 不代表长期保持 |
| E3 | 延迟且跨形式的无提示提取 | 间隔后换游戏/任务再次首答正确 | 不代表永久掌握 |

硬规则：

- G03 的选项配对属于支持式识别，证据上限 E1；不能因配对成功或路径通关升级为 E2。
- 提示、候选数量、部分字母、重试、任务类型和辅助方式必须影响证据上限。
- `route_bonus`、金币、连击、速度、Boss 阶段、游戏通关不得进入 E0–E3 输入。
- `N/A` 是合法维度状态，不得把不适用伪装成错误或零掌握。
- Learning Core 根据任务合同、提示情况和权威判定生成 StudyEvidence；Phaser/React/动画层不得直接写掌握度。
- 本地练习事件必须标记 `origin=local`；不得伪装成服务端确认。
- 48 小时窗的精确起止、重试次数、提示等级映射、E2/E3 升级规则目前未定义，标记【待确认】；在规则和测试表冻结前不得授予相关 E3。

### 5.3 +1 / +7 跨玩法复测

- D0 初次接触：允许必要示范/提示，记录曝光和 supportLevel。
- D0 当次无提示复现：换一种任务表达，不复用原题干/选项。
- D+1：约 24 小时后换游戏/任务形式，先答后反馈，记录实际间隔与首答。
- D+7：约 7 天后在新游戏/新语境复测，不重复原句。
- 错过复测不扣分、不清空进度、不制造连续登录惩罚。
- 具体到期容差、48 小时窗、重试和 E3 判定必须进入可执行测试表；当前为【待确认】。

## 6. 游戏事件、学习事件与会话契约

### 6.1 三类数据必须分离

1. **GameEvent**：描述游戏状态变化，如配对、路线、棋盘、机关、阶段、动画触发依据。
2. **StudyEvent / StudyEvidence**：描述某个 word/sense 在某个维度上的语言任务、支持等级、尝试、判定和证据。
3. **Progress / Reward**：描述关卡完成、收藏、路线奖励、图鉴、装饰和游戏表现。

三者不能用一个 `result_events` 数组混合，也不能从游戏表现反推学习证据。

### 6.2 事件字段候选

| 字段 | 用途 | 权威/约束 |
|---|---|---|
| `eventId` | 事件唯一身份 | 稳定唯一；重试不得重复计数 |
| `idempotencyKey` | 写请求幂等 | 服务端写操作必须有幂等键或稳定 eventId |
| `sessionId` | 会话关联 | 会话启动时创建，快照与事件引用一致 |
| `gameId / gameVersion` | 游戏身份与版本 | 必须匹配注册表 |
| `logicVersion` | 规则版本 | 重放使用原版本 |
| `schemaVersion` | 事件结构版本 | 结构变更可迁移/拒绝，不静默解释 |
| `contentPackId / contentPackVersion` | 内容版本 | 会话中途不静默换包 |
| `wordId / senseId` | 词条/义项 | 来自已加载内容包；任务唯一绑定一个 sense |
| `taskId / taskVariantId` | 任务定位 | 由 TaskFactory/内容模板生成 |
| `dimension / taskType` | 目标能力 | 由任务合同声明，不根据动画/分数反推 |
| `supportLevel / hintState` | 提示与辅助 | 影响证据上限 |
| `attemptIndex / retryState` | 尝试和重试 | 区分首答、重试；重复请求不重复计数 |
| `answerIntent` | 玩家答案意图 | 只记录最小必要输入，不采集原始键盘/触控时序 |
| `verdict / evidenceLevel` | 判定和证据 | 本地与服务端确认状态必须区分；客户端不得伪造服务端权威结果 |
| `source` | 事件来源 | `route_bonus` 完全排除出证据计算 |
| `occurredAt / acceptedAt` | 时间审计 | 记录实际时间和服务端接受时间，不用操作速度判学习能力 |

以上字段是 P0-0 候选合同，不代表已存在于当前代码。正式冻结前必须完成 Zod schema、OpenAPI、fixture、重放与幂等测试。

### 6.3 会话状态机候选

`created → ready → running → paused → completed`，并定义 `abandoned`、`interrupted`、`recovering`、`incompatible` 等异常/恢复状态。

- 每次重要逻辑状态转移后写入最小快照。
- 快照只保存逻辑状态，不保存 Phaser Scene、纹理、音频实例、DOM 节点。
- 恢复时必须校验 logicVersion、schemaVersion、contentPackVersion。
- 版本不兼容时不得静默套用新规则；明确提示继续本地旧版本、升级迁移或放弃该局。
- `dispose()` 必须可重复调用并清理事件监听、计时器、音频和资源引用。

- API-02/03 的内容包必须不可变并带 contentHash；正在进行的会话固定启动时版本。
- 当前无运行时 fixture、HTTP 状态码、数据库读回或服务端日志；不得写“API 已联调”。

### 7.1 新 API fixture 计划

服务端实现后使用独立测试档案与测试词包执行：

- API-01：健康检查成功/服务不可用时的错误结构。
- API-02/03：内容包清单、版本 manifest、hash、缺失版本、非法版本。
- API-04/05：无效激活码、重复兑换幂等、过期/撤销权益、未登录或匿名档案边界。

- API-08/09：监护人授权、导出范围、删除传播、重复删除、删除后离线补传过滤。
- 所有 fixture 保存原始请求/响应、HTTP 状态码、requestId、服务端日志和数据库读回。

## 9. 无障碍、输入公平与设备门

### 9.1 统一输入

触控、鼠标、键盘最终映射为同一语义动作；操作错误与语言错误分开。

- hover 不能是唯一信息入口。
- 拖动必须有点击选择或键盘替代路径。
- 不以高精度拖动、快速点击或手指速度判断学习能力。
- 拼写输入必须处理 IME compositionstart/compositionend；输入法组合态不得提前判错。
- 重要状态必须有 DOM 文本/状态播报；不能把 Phaser Canvas 当作完整读屏界面。

### 9.2 设备与视口

- 手机：360×640、390×844，另测窄屏、旋转和地址栏收缩。
- 平板：768×1024、1024×768。
- 桌面：1280×720、1366×768、1920×1080。
- 触控目标建议至少 44×44 CSS px（空间允许时）。
- 覆盖 Android Chrome、iOS Safari、Windows Chrome/Edge；平板单独记录。
- 慢速、暂停、静态、减少动态效果模式功能等价，不降低学习权益或证据等级。
- 房1先做 DOM/SVG 对照可行性实验；房2/房3独立回归。若关键流程读屏不可达，必须降级为 DOM/SVG 等价交互或调整玩法。

### 9.3 输入法与儿童可理解性

- 拼写矿车至少在两款国产输入法上验证组合输入、候选确认、退格、大小写和合法变体。
- 低端真实设备下限尚未确认。
- 儿童可理解性量表需先验证题项、评分者一致性和信度；不能用一次试玩主观反馈代替。

## 10. 隐私、儿童安全、删除与回滚

### 10.1 最小化原则
