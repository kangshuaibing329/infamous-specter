## 3. 三类事件合同

### GameEvent
只记录游戏规则状态变化：棋盘、路径、机关、部件、阶段、动画触发依据。不得包含客户端自报掌握度。

### StudyEventIntent
只提交语言任务的最小答案意图和上下文：wordId、senseId、taskId、dimension、taskType、认知支持、attemptIndex、contentPackVersion、evidencePolicyVersion。不得由客户端提交 verdict、evidenceLevel 或 masteryScore。

### ProgressEvent
只记录游戏表现和奖励：关卡、收藏、地图、装饰、route_bonus。不得进入 E0–E3。

所有客户端待同步事件都带 `origin=local`。服务端确认结果通过独立 EventDecision 返回，不允许客户端把本地事件伪装为 server_confirmed。

## 4. 幂等和版本边界

- 写请求带 `Idempotency-Key`；事件使用稳定 `eventId`。
- 同一 eventId 重传不重复计数、发奖或创建复习状态。
- 会话固定 `gameVersion + logicVersion + schemaVersion + contentPackId + contentPackVersion`。
- 服务端按原内容版本和任务合同重判，不信任客户端结论。
- 删除后离线待同步事件必须过滤，不能复活已删除档案。
- 旧项目 `/api/activity/*` 路由、字段、数据库和 adapter 均不允许进入新项目。

## 5. 12 项 fixture 覆盖

1. Health 成功/不可用；
2. 内容包列表；
3. manifest hash 不一致；
4. 激活码重复兑换幂等；
5. 权益过期；
6. 同 eventId 重复提交；
7. 未知 wordId/senseId；
8. 客户端伪造 verdict/evidenceLevel/masteryScore；
9. route_bonus 冒充 StudyEvent；
10. 旧 contentPackVersion；
11. 部分失败后同批次重试；
12. 删除后仍有离线事件。

## 6. 静态合同检查

本轮静态检查结果：
- OpenAPI JSON 可解析，版本 3.1.0；
- 9 个路径；
- 35 个内部 schema 引用均能定位到 components.schemas；
- 事件 schema 将三类事件分开；
- 三类客户端事件都要求 origin=local；
- StudyEventIntent 要求 evidencePolicyVersion。

以上不是 OpenAPI linter 或 JSON Schema 专用验证器的运行结果，也不是 API 集成测试。
