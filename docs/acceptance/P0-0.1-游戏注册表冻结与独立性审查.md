# P0-0.1｜十款游戏注册表冻结与独立性审查

- 版本：P0-0.1 / 0.1.0
- 适用仓库：`kangshuaibing329/infamous-specter`
- 状态：**结构基线候选冻结；G01/G10 产品裁决仍待确认**
- 关联文件：`docs/contracts/game-registry.candidate.v0.1.json`
- 前置：产品总方案 V2、PLAN-V3、十款游戏玩法设计、TECH-ARCH-V0.1

## 1. 本阶段裁决

十款游戏以注册表方式管理；每款必须有不同的核心循环、玩家动作、语言任务、游戏状态变化和可重放事件。共用的是启动、暂停、输入、存档、音频、内容包和学习证据服务，不共用一套换皮答题模板。

**结构冻结范围：** G01–G10 的 ID、名称、目标玩法方向、主语言动作、主要学习维度、关键事件类型、风险与验收门。  
**不冻结范围：** 每关具体关卡数值、最终美术、音效、题目文案、教材词条、正式关卡数量和 G01/G10 最终产品裁决。

## 2. 十款游戏独立性矩阵

| ID | 游戏 | 玩家主要动作 | 语言动作 | 游戏状态变化 | 不可被其他游戏替代的体验 |
|---|---|---|---|---|---|
| G01 | 词岛大冒险 | 探索、选择路线、触发机关 | 识义/语境决策 | 地图分支、机关和可达区域变化 | 英语判断决定探索路径，而不是只在地图上答题 |
| G02 | 拼写矿车 | 输入、排列或组装字母/词形部件 | 拼写产出/词形构造 | 轨道、矿车部件、前进路线变化 | 词形产出直接构成物理轨道或部件 |
| G03 | 词语连连看 | 选中配对、规划路径、处理棋盘死局 | 识义/听辨 | 棋盘连通、障碍、配对和重排变化 | 配对正确与路径合法是两套独立规则 |
| G04 | 词块消消乐 | 主动选择语义组合并消除 | 语义分类/语境判断 | 棋盘区域解锁、受控级联 | 语义正确是消除前置条件，随机消除不能推进学习 |
| G05 | 音速滑板 | 听音、选择车道、控制路线 | 听辨/识义 | 车道、路线和障碍状态变化 | 听觉输入驱动路线选择；速度不是学习指标 |
| G06 | 变形工厂 | 组合词根、词缀、词形部件 | 词形构造 | 生产线和目标词形变化 | 组合的是语言形态规则，不是普通字母排序 |
| G07 | 句桥救援 | 排列词块、修复或构造句子 | 语境/句法组织 | 桥梁分段连接、救援路径变化 | 需要构造完整句子，允许多个审核通过的合法答案 |
| G08 | 易混词侦探城 | 对比两个易混词、选辨析理由 | 易混辨析 | 线索板/排除结果变化 | 对比对象明确，核心问题是“这两个词差在哪里” |
| G09 | 线索地牢 | 自由顺序查看线索、缩小候选集、提交假设 | 上下文推断 | 候选集合逐步收敛、门锁状态变化 | 从多条上下文线索推断未知词，不是比较固定的一对词 |
| G10 | 岛心巨像 | 多阶段挑战、跨玩法应对 | 五维迁移/延迟提取 | Boss 阶段状态变化 | 多阶段任务编排；每阶段必须有不同语言动作，Boss 血量不是掌握度 |

## 3. 重点同质化审查

### 3.1 G08 与 G09

| 比较点 | G08 易混词侦探城 | G09 线索地牢 |
|---|---|---|
| 任务起点 | 已知一组易混词 | 一个待推断的目标词 |
| 主要问题 | 两个词如何区分 | 多条线索指向哪个词 |
| 候选空间 | 通常固定为一组对比项 | 多候选集合，逐步缩小 |
| 主要操作 | 对比词形/发音/词义并选理由 | 选择线索、排除候选、形成假设 |
| 失败表现 | 辨析维度或理由错误 | 线索解释错误/候选集合收敛失败 |
| 通过门 | 对比项和理由有明确语言依据 | 任意允许线索顺序均可解，目标唯一 |

**阻断规则：** 如果实际原型都变成“看题干→选一个单词”，G08/G09 不通过独立性验收。必须重做操作循环，不允许仅靠场景、名称和美术差异算两款游戏。

### 3.2 G01 与游戏大厅

G01 必须让英语判断改变路线、机关、区域状态或可达性。若玩家只是浏览地图、点击游戏入口或领取装饰，它就是全局地图/大厅，不是独立游戏。若反事实重放证明英语输入不会改变游戏状态，G01 降级为大厅功能；是否仍计入十款由产品所有者裁决。

### 3.3 G10 与“单词怪兽战”

“单词怪兽战”暂作为 G10 的 Boss 阶段/机制候选，不自动新增 G11。G10 每个阶段必须声明 `wordId + senseId + dimension + taskType`，并能单独回放；Boss 血量、阶段通过、伤害值和奖励均不属于学习证据。

### 3.4 G04 风险门

G04 是条件开发项，不进入 P3 三款先导。只有玩家主动发起且语义判定通过的消除才能产生正向解锁；级联只清理已解锁区域，不生成新的语言学习证据。专项验证失败时回滚到无支援原型并延后。

## 4. 统一模块边界

- React：游戏大厅、内容包选择、设置、学习报告、提示文本、键盘焦点与 DOM 语义。
- Phaser：场景、地图、棋盘、动画、音效和游戏内视觉表现。
- Game Core（纯 TypeScript）：规则、状态机、合法动作、seed/replay 和游戏事件。
- Learning Core：词义任务、答案判定、提示策略、证据分级、复习调度。
- Content Service：版本化词包、词义、音频、例句、资源和任务模板。
- Save Service：IndexedDB 持久化、快照、迁移和恢复。
- API：新项目独立的 `/api/v1/*`；不继承旧项目 API 或数据库。

每款游戏必须实现统一控制器生命周期：`mount/start/pause/resume/dispatch/getSnapshot/restore/dispose/subscribe`。游戏模块不得直接访问数据库、直接写掌握度或自行维护一份正确答案副本。

## 5. C1 独立性可执行门

每种机关、路线或主要交互机制建立一个三元组：

1. **语言输入/判断**：唯一明确的 word/sense/task/dimension。
2. **游戏状态差异**：通过规则层状态转移证明输入对路径、棋盘、部件或阶段有因果影响。
3. **可重放事件**：记录 action、taskRef、判定引用、stateBefore/stateAfter、seed 和 logicVersion。

### 5.1 反事实回放

每个机制至少执行以下三组：

- 正确语义输入：应触发规格声明的正向状态变化。
- 同分布随机输入：只能在随机输入碰巧符合正确答案时触发同一合法结果；不能凭随机操作绕过判题。
- 固定错误输入：不得触发正向语言结果或学习证据；只能进入定义好的错误恢复状态。

### 5.2 硬阈值

- 机制清单覆盖率：100%。
- 未判定为正确的输入触发正向语义状态变化：0 次。
- 由动画回调直接写入 StudyEvidence：0 次。
- 路线/奖励事件进入 E0–E3：0 次。
- 同 seed、同版本、同 action 序列的逻辑回放结果：完全一致。
- 机制没有可说明的语言因果链：不通过，删除或降级。

## 6. 首批先导与顺序

P3 三款先导候选：G03 词语连连看、G02 拼写矿车、G10 岛心巨像。选择理由是分别覆盖配对/路径、拼写产出、多阶段综合迁移，便于验证共享内容和学习证据合同。

G04 不进入先导；G08/G09 先完成差异化规格；G01 先证明独立循环。其余游戏按 P3 结果逐款进入，不同时开启十条开发线。
