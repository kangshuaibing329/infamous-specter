# P1｜共享底座实现计划与阶段验收

- 版本：P1-PLAN-0.1
- 分支：codex/p1-learning-core-v0.1
- 基线：T1 技术样板分支 + P0 内容包/学习证据合同
- 目标：把三套词库从静态文件接入可校验的本地内容层、Session Adapter、Learning Core 和本地持久化；实现受限的只读内容 API。
- 非目标：正式十款游戏玩法、儿童账号/监护人账号、付费激活、跨设备同步、生产部署。

## 1. 实施原则

1. 不改写 T1 Phaser 技术样板的已验证边界；新能力放入独立 workspace package。
2. 内容包以 JSON 为唯一规范主数据；CSV 是编辑/导入视图。
3. 每个 Session 固定 `packId + version + gameId + logicVersion + schemaVersion`。
4. Learning Core 接收答案意图和任务合同；游戏层不自报掌握度。
5. E0–E3 是学习证据，不是游戏分数。P1 本地模式生成 provisional evidence，不能伪装为服务端确认。
6. 客户端待同步事件保留 `origin=local`；P1 暂不实现云同步。
7. Preview 包只允许内部样板使用，不进入客户可选 API；当前三包均 customerSelectable=false。
8. 未审核音频不生成 listening 任务；没有明确构词规则不生成 morphology 任务。

## 2. P1 模块拆分

| 模块 | 主要职责 | 交付 |
|---|---|---|
| packages/contracts | 内容、任务、会话、事件的共享 TypeScript 类型 | 类型与边界测试 |
| packages/content | JSON Schema 运行时校验、内容包索引、词义/任务引用检查 | Ajv 2020 validator、加载 API |
| packages/learning-core | AnswerEvaluator、HintPolicy、EvidenceRecorder、ReviewScheduler | 纯函数、30+ 单元测试 |
| packages/session-adapter | Session 创建、词包版本固定、任务映射、会话快照 | Session API 与确定性测试 |
| packages/storage | Dexie 数据库迁移、内容包/会话/事件仓储、幂等写入 | IndexedDB 测试 |
| apps/api | Fastify health、公开内容包列表、不可变 manifest 只读接口 | HTTP inject 集成测试 |
| apps/web | P1 本地学习核心验收台；展示候选包状态、任务流程、证据日志 | Playwright 样板测试 |

## 3. P1 分阶段执行

### P1.1 内容运行时
- 引入 Draft 2020-12 schema validator。
- 对 JSON 文件执行 schema + 语义引用 + wordCount + hash 检查。
- 提供 `listLocalContentPacks`、`loadContentPack`、`getTasksForSense`。
- Preview 候选需明确标记，禁止被当作 published。

### P1.2 Session Adapter
- 创建 session 时必须传入明确 packId/version。
- 校验游戏 ID 与任务模板兼容性。
- 任务队列可由 seed 确定性生成；会话过程中不热更新内容版本。
- 保存任务进度、attemptIndex 和 cognitiveSupport。

### P1.3 Learning Core
- 严格区分技术输入错误、无效输入和有效答案。
- 认知支持：none 可达到 E2（同次首答）；choice/hint/clue/partial answer 最高 E1；worked example/answer revealed/guided follow-along 最高 E0。
- 同次答错后再答对最高 E1。
- E3 需要 D+1/D+7 时间窗口、首答无提示、不同 gameId、不同 taskType、同一已审核 sense；本地 P1 不伪造延迟锚点。
- 事件保留原始答案意图和版本信息；客户端不提交 verdict/evidenceLevel/masteryScore。

### P1.4 本地持久化
- Dexie 数据库升级，保留 T1 labStates。
- 新增 contentPacks、sessions、studyEvents、gameEvents、reviewStates。
- eventId 幂等；重复写入不重复生成复习记录。
- 事件日志为事实源，reviewStates 为可重建派生数据。

### P1.5 只读内容 API
- 实现 GET /api/v1/health。
- 实现 GET /api/v1/content-packs，仅返回 customerSelectable=true 且状态 published/preview 的包。
- 实现 GET /api/v1/content-packs/{packId}/versions/{version}/manifest。
- 不实现未确认身份模型的 activation、entitlements、sync、privacy 写接口。
- API 不能向客户暴露 customerSelectable=false 的内部样本包。

### P1.6 集成与验收
- Vitest：内容 schema、引用完整性、Session pinning、答案评估、证据边界、幂等和复习状态。
- Fastify inject：健康检查、内容列表、manifest、404/409。
- Playwright：选择内部样本包、开始本地 session、提交答案、保存和恢复。
- GitHub Actions：typecheck、unit tests、build、API integration、E2E 全部通过才标记对应门通过。

## 4. 当前依赖和阻断

- T1 PR #1 仍是独立技术样板分支；P1 分支以该分支为父基线。
- P0 PR #2 与词库 PR #3 仍需按顺序合并，P1 先以候选合同副本开发。
- 三套词包未教研审核、音频缺失、版权/来源审核待完成，因此只作为 internal preview。
- 监护人/匿名档案身份模型、服务端数据地域、付费权益和同步范围未裁决，P1 不实现相关接口。

## 5. P1 通过标准

- 所有运行时包通过 schema + 语义检查；内容版本固定。
- 无法通过客户端字段伪造 E0–E3；E3 不在本地直接确认。
- 同 eventId 重放不重复计数；本地事件 origin 固定 local。
- 复习状态可从事件重建。
- API 只返回获准可见内容包；候选样本包不可公开列出。
- T1 技术样板的已有自动化回归保持通过。
- 未执行的真机、读屏、儿童隐私和生产服务端测试继续标记 NOT_RUN。
